# 股票数据自动更新脚本 - 使用说明

## 🎯 智能更新模式（新功能）

脚本现在支持**智能跳过**功能，自动跳过已更新到最新的股票，只处理需要更新的股票。

### 主要优化

1. **智能筛选**：启动时自动检测哪些股票需要更新
2. **优先级排序**：
   - 优先更新从未导入数据的股票
   - 按数据过时程度排序（最旧的优先）
3. **进度可视化**：显示实时更新进度和预计剩余时间
4. **无需重复更新**：已是最新的股票会被自动跳过

### 使用方法

#### 1. 智能更新模式（推荐）

```bash
# Windows PowerShell
cd D:\比赛\金融分析项目\financial_analysis\financial-analysis-api
python scripts\auto_update.py --run-once
```

**特点**：
- ✅ 自动跳过已更新到最新的股票
- ✅ 只更新需要的股票，节省时间和API调用
- ✅ 显示详细的更新队列信息

**日志示例**：

#### 2. 全量更新模式

```bash
# 禁用智能跳过，更新所有股票（包括已是最新的）
python scripts\auto_update.py --run-once --no-smart-skip
```

**特点**：
- 处理所有股票（包括已是最新的）
- 适用于验证数据完整性的场景
- 执行时间较长

#### 3. 更新单只股票

```bash
# 更新平安银行
python scripts\auto_update.py --stock SZ000001

# 更新贵州茅台
python scripts\auto_update.py --stock SH600519
```

#### 4. 定时自动更新

```bash
# 每天20:00自动更新（智能模式）
python scripts\auto_update.py --run-scheduler --time 20:00
```

## 📊 更新流程

### 智能模式流程

```
1. 连接数据库，获取最近交易日
   ↓
2. 查询需要更新的股票列表
   - 检查：无数据 OR 数据日期 < 最近交易日
   - 排序：无数据优先，然后按日期从早到晚
   ↓
3. 遍历更新队列
   - 对每只股票：从最新日期+1天 到 今天
   - 调用Tushare API获取数据
   - 插入数据库（INSERT IGNORE去重）
   ↓
4. 输出更新统计
   - 成功/失败/跳过数量
   - 新增记录条数
   - 总耗时和平均速度
```

### 数据完整性保障

- **增量更新**：只获取缺失的日期范围
- **去重保护**：使用 `INSERT IGNORE` 避免重复插入
- **错误重试**：失败后自动延长延迟时间
- **频率控制**：默认1.5秒/次，避免触发API限制

|------|------|--------|

## 🛠️ 故障排查

### 问题1：更新很慢

**可能原因**：
- 使用了全量模式（`--no-smart-skip`）
- 数据库连接慢
- 网络延迟高

**解决方案**：
```bash
# 使用智能模式
python scripts\auto_update.py --run-once
```

### 问题2：频繁失败

**可能原因**：
- Tushare API频率限制
- Token积分不足
- 网络不稳定

**解决方案**：
```bash
# 增加延迟时间（默认1.5秒，可在代码中修改）
# 或者在代码中修改 delay_seconds 参数
```

### 问题3：数据库连接失败

**检查步骤**：
1. 确认数据库服务正在运行
2. 检查 `.env` 文件中的数据库配置
3. 测试数据库连接：
   ```bash
   mysql -h localhost -u root -p
   ```

### 问题4：部分股票一直跳过

**可能原因**：
- 停牌或退市
- 数据库中已有最新数据

**检查方法**：
```sql
-- 查看某只股票的最新日期
SELECT MAX(trade_date) FROM stock_daily_data WHERE stock_code = 'SZ000001';

-- 查看哪些股票需要更新
SELECT sbi.stock_code, MAX(sdd.trade_date) as latest_date
FROM stock_basic_info sbi
LEFT JOIN stock_daily_data sdd ON sbi.stock_code = sdd.stock_code
GROUP BY sbi.stock_code
HAVING latest_date IS NULL OR latest_date < CURDATE()
ORDER BY latest_date ASC
LIMIT 10;
```

## 📝 注意事项

1. **API限制**：
   - 基础积分：每分钟500次
   - 脚本默认1.5秒/次，约40次/分钟
   - 安全范围内，不会触发限制

2. **数据延迟**：
   - 当日数据通常在收盘后1-2小时可用
   - 建议设置定时任务在20:00执行

3. **数据库空间**：
   - 4500只股票 × 10年数据 ≈ 1100万条记录
   - 预计占用约 5-10 GB 磁盘空间

4. **断点续传**：
   - 脚本支持中断后继续
   - 已更新的数据不会重复插入（INSERT IGNORE）
