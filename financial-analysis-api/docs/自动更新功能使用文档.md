# 股票历史行情自动更新功能使用文档

## 一、功能概述

本系统提供了自动更新股票历史行情数据的功能，支持：

- ✅ **每日定时自动更新**：每天晚上 8 点自动更新所有股票数据
- ✅ **启动时自动更新**：服务器启动时可选择立即更新到最新日期
- ✅ **交易日智能判断**：休市日自动跳过，避免无效 API 调用
- ✅ **增量更新**：从数据库最新日期的下一天开始更新，避免重复
- ✅ **全覆盖**：自动更新所有约 4500+ 只股票
- ✅ **API 限制保护**：添加请求延迟，避免被 Tushare 封禁
- ✅ **详细日志记录**：所有操作都有详细日志，方便追踪和调试

## 二、配置说明

### 2.1 环境变量配置

在 `.env` 文件中配置以下变量：

```bash
# Tushare API Token（必填）
TUSHARE_TOKEN=your_tushare_token_here

# 启用自动更新（1=启用, 0=禁用）
ENABLE_AUTO_UPDATE=1

# 每天自动更新的时间（格式：HH:MM）
AUTO_UPDATE_TIME=20:00

# 服务器启动时是否立即更新（1=是, 0=否）
AUTO_UPDATE_ON_STARTUP=0

# 数据库配置（必填）
DATABASE_HOST=localhost
DATABASE_USER=root
DATABASE_PASSWORD=your_password
DATABASE_NAME=financial_analysis_db
```

### 2.2 配置项说明

| 环境变量 | 默认值 | 说明 |
|---------|--------|------|
| `TUSHARE_TOKEN` | - | Tushare Pro API Token（在 tushare.pro 注册后获取） |
| `ENABLE_AUTO_UPDATE` | `0` | 是否启用自动更新功能 |
| `AUTO_UPDATE_TIME` | `20:00` | 每天自动更新的时间（建议 20:00 之后） |
| `AUTO_UPDATE_ON_STARTUP` | `0` | 启动时是否立即执行一次更新 |

## 三、使用方式

### 3.1 方式一：集成在 FastAPI 服务中（推荐）

在 `.env` 中设置：

```bash
ENABLE_AUTO_UPDATE=1
AUTO_UPDATE_TIME=20:00
AUTO_UPDATE_ON_STARTUP=1  # 可选：启动时立即更新
```

然后正常启动 FastAPI 服务：

```bash
python main.py
# 或
uvicorn main:app --reload
```

服务启动后：
- 如果 `AUTO_UPDATE_ON_STARTUP=1`，会在后台线程立即执行一次更新
- 定时调度器会在每天 20:00 自动执行更新
- 控制台会显示启动信息和更新进度

### 3.2 方式二：独立运行脚本

#### 立即执行一次更新（测试用）

```bash
python scripts/auto_update.py --run-once
```

适用场景：
- 测试自动更新功能
- 手动触发一次全量更新
- 首次导入历史数据后的增量更新

#### 启动定时调度器（独立运行）

```bash
python scripts/auto_update.py --run-scheduler
```

适用场景：
- 不想启动 FastAPI 服务，但需要定时更新
- 在独立的进程中运行定时任务

#### 自定义更新时间

```bash
python scripts/auto_update.py --run-scheduler --time 21:30
```

#### 更新单只股票（调试用）

```bash
python scripts/auto_update.py --stock SH600000
```

## 四、工作原理

### 4.1 更新流程

```
1. 检查是否为交易日
   ├─ 是 → 继续
   └─ 否 → 跳过更新，记录日志

2. 从数据库获取所有股票代码（约 4500+ 只）

3. 逐只更新股票数据：
   ├─ 查询数据库最新日期
   ├─ 如果最新日期 >= 今天 → 跳过
   ├─ 否则从最新日期+1天开始更新
   ├─ 调用 Tushare API 获取数据
   ├─ 插入数据库
   └─ 延迟 0.12 秒（避免 API 限制）

4. 统计并记录结果
```

### 4.2 交易日判断

- 通过 Tushare `trade_cal` API 获取上交所交易日历
- 判断当前日期是否为交易日（`is_open=1`）
- 如果 API 失败，简单判断周末为休市日

### 4.3 API 限制保护

Tushare API 限制（基础积分）：
- 每分钟最多 500 次调用
- 每次最多返回 6000 条数据

保护措施：
- 每次请求后延迟 0.12 秒（即 500 次/分钟）
- 出错后延迟加倍（0.24 秒）

### 4.4 数据一致性保障

- 从数据库最新日期的下一天开始更新，避免重复插入
- 如果最新日期已是今天，跳过更新
- 首次导入从 2015-01-01 开始

## 六、常见问题

### 6.1 更新时间过长怎么办？

**预期时间**：约 4500 只股票 × 0.12 秒/只 ≈ **9-15 分钟**（取决于网络和数据量）

**优化建议**：
- 保持网络稳定
- 避免高峰期更新
- 如果首次导入大量历史数据，可能需要几小时

### 6.2 为什么有些股票更新失败？

可能原因：
- 股票已退市或停牌
- Tushare API 暂时无数据
- 网络波动

**处理方式**：
- 查看日志中的具体错误信息
- 失败的股票会自动跳过，不影响其他股票
- 下次更新时会重试

### 6.3 休市日会更新吗？

**不会**。系统会通过 Tushare 交易日历 API 判断是否为交易日，休市日会自动跳过。

休市日包括：
- 周末（周六、周日）
- 法定节假日（春节、国庆等）
- 特殊休市日

### 6.4 如何查看更新进度？

1. **控制台输出**：每 100 只股票显示一次进度
2. **日志文件**：查看 `logs/stock_data_update.log`
3. **数据库查询**：

```sql
-- 查看最新更新日期
SELECT MAX(date) FROM stock_daily_data;

-- 查看各股票最新日期
SELECT stock_code, MAX(date) as latest_date
FROM stock_daily_data
GROUP BY stock_code
ORDER BY latest_date DESC
LIMIT 10;

-- 统计数据量
SELECT COUNT(*) as total_records FROM stock_daily_data;
```

### 6.5 如何测试自动更新功能？


## 八、技术细节

### 8.1 数据表结构

```sql
CREATE TABLE stock_daily_data (
    id INT AUTO_INCREMENT PRIMARY KEY,
    stock_code VARCHAR(20) NOT NULL,
    date DATE NOT NULL,
    open DECIMAL(10,2),
    high DECIMAL(10,2),
    low DECIMAL(10,2),
    close DECIMAL(10,2),
    pre_close DECIMAL(10,2),
    change_amount DECIMAL(10,2),
    change_percent DECIMAL(10,4),
    volume BIGINT,
    amount DECIMAL(20,2),
    UNIQUE KEY uk_stock_date (stock_code, date),
    FOREIGN KEY (stock_code) REFERENCES stock_basic_info(stock_code)
);
```

### 8.2 核心类和方法

| 类/方法 | 说明 |
|--------|------|
| `StockDataAutoUpdater` | 自动更新核心类 |
| `is_trading_day()` | 判断是否为交易日 |
| `get_latest_trade_date()` | 获取数据库最新日期 |
| `update_single_stock_data()` | 更新单只股票 |
| `batch_update_stocks_data()` | 批量更新所有股票 |
| `start_background_scheduler()` | 启动后台定时任务 |

### 8.3 依赖库

- `tushare`：数据源 API

## 九、故障排除

### 9.1 Token 无效

**错误信息**：`token 无效`

**解决方法**：
1. 检查 `.env` 中的 `TUSHARE_TOKEN` 是否正确
2. 访问 https://tushare.pro/ 确认 Token 状态
3. 确认 Token 有足够积分

### 9.2 数据库连接失败

**错误信息**：`无法连接数据库`

**解决方法**：
1. 检查数据库服务是否启动
2. 验证 `.env` 中的数据库配置
3. 测试连接：`mysql -h localhost -u root -p`

### 9.3 API 频率限制

**错误信息**：`抱歉，您每分钟最多访问该接口500次`

**解决方法**：
- 系统已自动添加延迟保护
- 如果仍触发限制，可增大延迟：
  ```python
  updater.batch_update_stocks_data(delay_seconds=0.15)
  ```

### 9.4 定时任务未执行

**检查步骤**：
1. 确认 `ENABLE_AUTO_UPDATE=1`
2. 查看启动日志是否有 "自动更新调度已启动"
3. 检查系统时间是否正确
4. 查看 `logs/stock_data_update.log` 是否有执行记录
